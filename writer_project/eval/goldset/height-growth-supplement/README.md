# 골드셋 쿼리 작성 가이드 — height-growth-supplement

## 목적

`gemini-embedding-001`(3072d)이 현 운영 모델 `text-multilingual-embedding-002`(768d)를
한국어 단문 retrieval에서 이기는지 사전 평가하기 위한 (쿼리, 정답 청크) 골드셋을 만든다.

이 골드셋의 품질이 평가 신뢰도의 상한선이다.

## 평가 설계 (참고)

운영 `_dual_retrieve`는 local store와 web store에서만 검색하고 score 머지 후 top-k 반환한다.
(통합 store는 `CHROMA_INCLUDE_BASE=False` 기본값으로 사용 안 함, `MERGE_RETRIEVE_MODE=web_first` 기본값.)

따라서 평가도 두 층위로 본다:

- **층위 1** (clean 신호): local 청크 안에서, web 청크 안에서 각각 ranking 평가.
  임베딩 모델 자체의 store-내부 품질만 깨끗이 측정.
- **층위 2** (운영 정렬): local + web 합친 통합 풀에서 ranking 평가.
  운영 `_dual_retrieve`가 머지 후 top-k 반환하는 시점과 정렬.

두 층위 다 한 번 임베딩하면 산출되므로 골드셋 작성 시 신경 쓸 것 없음.

## 작업 흐름

1. `chunks_sampled.jsonl` 을 VS Code 등으로 연다.
2. 각 줄은 한 청크. `text` 필드를 읽고, 어울리는 한국어 단문 쿼리를 `query` 필드에 입력한다.
3. **store별로 15~20개씩, 총 30~40개**가 채워지면 충분. 50개 다 채울 필요 없다.
4. 애매한 청크는 `query` 빈 채로 둔다 — 평가 단계에서 자동 제외된다.

### 왜 store별 균형?

층위 1에서 store별로 따로 ranking을 보는데, 한쪽 쿼리가 너무 적으면 그쪽 통계가 의미 없어진다.
local 17개 / web 18개 정도 균형이 이상적. 한쪽이 5개 미만이면 그 store는 평가 결과에서 빠진다.

## 작성 가이드라인

### 1) 단문 — 5~30자

운영에서 실제로 들어올 만한 검색어 길이.

- ✅ "키 크는 영양제 추천"
- ✅ "성장기 칼슘 부족 증상"
- ✅ "어린이 성장판 닫히는 시기"
- ❌ "안녕하세요, 제 아이가 초등학교 5학년인데 키가 또래보다 작아서 걱정인데..." (너무 김)
- ❌ "키" (너무 짧음, 변별력 없음)

### 2) 자연스러운 검색어 톤 — 격식체 X

실제로 사람이 검색창에 칠 만한 표현.

- ✅ "성장호르몬 부작용"
- ✅ "아연 어린이 권장량"
- ❌ "성장호르몬의 부작용은 무엇인가요?" (격식체)
- ❌ "Q. 아연 권장량을 알려주세요." (질문 형식)

### 3) 청크 표현 베끼기 금지 — paraphrase

청크에 있는 단어를 그대로 옮기면 임베딩 유사도가 인위적으로 부풀려진다.
두 모델의 변별력 평가가 망가지므로 반드시 다른 표현으로 바꿀 것.

청크 예시: "아르기닌은 성장호르몬 분비를 자극하는 아미노산으로 알려져 있습니다."

- ❌ "아르기닌 성장호르몬 분비 자극" (베끼기)
- ✅ "키 크는 데 도움 되는 아미노산"
- ✅ "성장기 어린이 영양제 성분"

### 4) 답이 청크에 *실제로* 있어야 함

추론으로 도달 가능하지만 청크에 직접 안 나오는 내용은 제외.
이건 retrieval 평가지 reasoning 평가가 아니다.

청크 예시: "비타민 D는 칼슘 흡수를 돕는다."

- ✅ "비타민D 칼슘 관계" (청크에 직접 있음)
- ❌ "키 크려면 햇볕을 쬐어야 하나요" (햇볕→비타민D 추론 필요)

### 5) 애매하면 스킵

- 청크가 너무 일반적이라 어떤 쿼리든 매칭될 것 같으면 스킵
- 청크가 너무 specific해서 자연스러운 쿼리가 떠오르지 않으면 스킵
- 광고/추천 톤이 강해 정보 retrieval에 부적합하면 스킵

## 진행 팁

- **세션 나눠서 OK**: 한 번에 다 안 해도 된다. 10개씩 세 번 나눠도 됨.
- **VS Code 권장**: jsonl 한 줄이 길면 word wrap 켜기 (Alt+Z).
- **store 필드 신경 X**: 자동으로 박힌다. 너는 text만 보고 쿼리 작성.
- **확신 없는 쿼리는 작성하지 말 것**: 골드셋 노이즈가 평가 결과 노이즈로 직결된다.

## 진행 후

쿼리가 store별 15+ 개씩 채워지면 다음 명령으로 평가 실행:

```powershell
python tools/eval_embedding_models.py
```

결과는 `eval/results/height-growth-supplement_gemini_vs_multilingual.md`에 저장된다.
